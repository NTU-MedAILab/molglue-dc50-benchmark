# Reproducibility deviation log v1

## OOD resume regeneration

During Stage 1 validation, the frozen OOD runner was invoked with `--resume`
against the completed formal result directory. Although no domain refit was
needed, the runner regenerated three derived bootstrap/aggregate CSV files and
run metadata from the serialized prediction artefacts:

- `ood_aggregate_metrics.csv`;
- `ood_domain_scaffold_bootstrap.csv`;
- `ood_paired_scaffold_bootstrap.csv`;
- `ood_run_manifest.json` metadata.

The regenerated floating-point values were scientifically unchanged but some
CSV bytes and last-bit representations differed from the historical inventory.
No prediction, split, selected hyperparameter, domain metric or scientific
configuration changed.

Resolution:

1. The historical inventory was retained as the comparison target.
2. A complete OOD run was executed in an isolated clean output directory using
   the pinned environment and frozen formal arguments.
3. The isolated reproduction recovered the exact historical SHA256 values for
   all three derived CSV files.
4. The reproduced manifest matched all scientific fields; only expected run
   timing/path metadata differed byte-for-byte.
5. `stage1_artifact_hash_audit.csv` records direct versus isolated-
   reproduction resolution for every artefact.

This event does not change any reported estimate. It is retained here because
silent normalization of the legacy directory or omission of the byte-level
difference would weaken the audit trail.

## Core reproduction command correction

The first clean core command omitted the explicit `--protocols scaffold
compound` argument. The runner's default executed only the scaffold protocol,
which reproduced 6/19 required scientific artefacts exactly but could not
satisfy the complete Stage 2 gate.

Resolution:

- the scaffold-only output was preserved as
  `reproduction/confirmatory_cpu_v1_scaffold_only`;
- a new isolated run was started with the full frozen formal arguments,
  including both scaffold and compound protocols;
- the complete run finished and the final comparison recovered all 19/19
  required scientific artefacts exactly; and
- the Stage 2 gate was updated to `PASS`.

The partial scaffold-only run was not used as evidence for the Stage 2 GO
decision.

## Source-deletion within-script baseline reconciliation

The new target-OOD source-deletion sensitivity includes a newly fitted
`deletion_source=none` comparator. For a VAV1 diagnostic, its ordered
train/test indices, four inner splits, model seeds, selected parameters and
feature dimensions matched the archived confirmatory OOD analysis. The new
predictions nevertheless differed from the archive by at most 0.011870
pDC50 for chemistry-only and 0.018532 pDC50 for chemistry plus context.
Changing between one and four model threads did not alter the discrepancy, so
thread count is not assigned as the cause.

The difference is recorded as unresolved non-bitwise reconstruction. It does
not enter a source-deletion contrast: every deletion condition is compared
only with the `none` fit generated by the same script and environment on
identical test rows and paired bootstrap draws. Full details are in
`docs/post_hoc_scaffold_source_baseline_reconciliation_v1.md`.

## Conditional-permutation parallel execution

The 100 frozen conditional label-randomization runs were divided into
non-overlapping identifier ranges for CPU wall-time reduction. An early
execution-identity test launched with the system Python rather than the
project lock and produced a different descriptor/software identity; it was
discarded in a temporary directory and never entered formal evidence.

The execution-only shard wrapper was then tested with the locked Python
3.10.19, scikit-learn 1.7.2 and RDKit 2025.09.4 environment. Permutation ID 1
matched the parent implementation exactly for model metrics, contrasts,
fold diagnostics and the feature manifest. Formal shards are accepted only
after fail-closed checks of complete identifier coverage, exact overlapping
rows, feature identity, within-stratum label multisets and a recoverable
pre-merge snapshot. Scientific randomization code, seeds and estimands are
unchanged. See
`docs/post_hoc_permutation_parallel_execution_deviation_log_v1.md`.
